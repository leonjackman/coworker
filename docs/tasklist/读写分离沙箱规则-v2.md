## 改动 1（workspace.py L54附近）：`READ_ONLY_COMMANDS` 集合

**已完成**: 新增 `READ_ONLY_COMMANDS = frozenset({...})` (20 个只读命令)

```python
READ_ONLY_COMMANDS = frozenset({
    "cat", "ls", "pwd", "head", "tail", "more", "less",
    "wc", "grep", "rg", "find", "file", "stat", "du", "df",
    "id", "whoami", "uname", "date", "echo",
})
```

测试通过：ls/cat 在白名单，git/python3/python 不在白名单。

## 改动 2（agents.py ~L833 `needs_command_approval`）：read-only 命令直走不 HITL

**已完成**: 添加 10 行代码判断 read-only 命令

- 从 `req.input.command` 提取执行命令 basename
- 检查是否在 `READ_ONLY_COMMANDS` 白名单
- 是 → `return False` (不 HITL，直走)
- 不在 → 继续原有逻辑（supervised 下仍 HITL）
- `"git"、"python3"` 等不在白名单 → 正常 HITL

API 测试通过：`exec/supervised` 下发送 `ls` 外部目录 → **0 次 HITL 中断**。

## 改动 3（agents.py ~L2900 `resume_interrupt`）：`run_command` 审批 → 允许外部 cwd

**已完成**: 在检查 write 工具 HITL 审批时，也检查 `run_command`

```python
if tool_name in ("write_file", "replace_in_file", "apply_text_edits", "run_command"):
```

**原因**：`run_command` 的 `cwd` 走 `resolve_write_path(cwd)`，复用 `_allow_external_write` 标志。

测试通过：外部 cwd 在 HITL 批准后可通过 `resolve_write_path`。
