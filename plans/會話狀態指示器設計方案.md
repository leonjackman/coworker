### 3.2 核心資料模型（前端）

新增 `frontend/src/types.ts`：

```ts
/** 單一會話的狀態徽章聚合結果。 */
export interface SessionBadges {
  running: boolean;      // 進行中
  approvals: number;     // 待審批筆數（0 = 無）
  unread: number;        // 未讀訊息數
  error: string | null;  // 錯誤摘要（null = 無錯誤）
}

/** sessionId → 徽章。取代現有的 runningSessionIds?: Set<string>。 */
export type SessionBadgeMap = Map<string, SessionBadges>;
```

`SessionSummary`（`types.ts:403`）擴充兩個唯讀欄位（由後端 `public()` 提供）：

```ts
export interface SessionSummary {
  // ...既有欄位
  unread_count: number;        // 後端由 last_read_at 計算
  last_error: string | null;   // 後端持久化的錯誤摘要
}
```

### 3.3 優先級規則（硬性）

左側狀態槽固定 16px，**永遠只顯示優先級最高者**：

```
待審批(approvals > 0)  >  錯誤(error != null)  >  進行中(running)
```

理由：待審批是阻塞（agent 卡住等人），錯誤是求救，進行中僅為資訊。未讀不參與競爭，獨立顯示在右側。

## 4. 後端設計

### 4.1 `Session` 欄位擴充

`backend/coworker/sessions.py:98` 的 `Session` dataclass 加兩個欄位：

```python
    # 會話級已讀水位線（ISO 8601 UTC）。空字串 = 從未讀取，視為全部已讀，
    # 以免升級後既有會話一次性爆出大量未讀。
    last_read_at: str = ""
    # 最近一輪以錯誤終止時的摘要（空字串 = 無錯誤）。隨 session JSON 持久化，
    # 供側欄錯誤指示器跨重啟顯示。
    last_error: str = ""
```

`from_dict`（`:137`）補讀取，舊檔自動相容：

```python
            last_read_at=str(payload.get("last_read_at", "") or ""),
            last_error=str(payload.get("last_error", "") or ""),
```

### 4.2 未讀＝計算值，不是計數器

`public()`（`:162`）輸出**計算出的** `unread_count`，不存計數欄位：

```python
    def unread_count(self) -> int:
        """未讀 = last_read_at 之後新增的 assistant 訊息數。

        用時間水位線而非計數器：不必在每個回合結束點掛 increment（容易漏掛、
        難以對齊流式寫入時機），也不會因漏掛而永久漂移。水位線自癒。
        """
        if not self.last_read_at:
            return 0
        return sum(
            1 for m in self.messages
            if m.role == "assistant" and m.created_at > self.last_read_at
        )
```

`public()` 補一行 `"unread_count": self.unread_count()`，並加 `"last_error": self.last_error or None`。

> **`created_at` 可直接字串比較**：`_now()`（`:11`）回傳 `datetime.now(timezone.utc).isoformat()`，固定 `+00:00` 偏移的 ISO 8601，字典序即時間序。

**為什麼不存計數器**：計數器必須在「每個 assistant 訊息落庫點」掛 `+1`，而專案裡 `append_message` 有 10 處呼叫（`main.py:2107/2160/2766/3343/4103/4137/4298/4332/5051`），漏一處就永久漂移，且重啟後無從校正。水位線只需一個欄位 + 一個讀取端點。

## 5. 前端設計

### 5.1 聚合層：`useSessionBadges`

新增 `frontend/src/lib/useSessionBadges.ts`（專案慣例：hook 放 `lib/`，見 `usePanelResize.ts`、`useUpdateCenter.ts`）。

```ts
export function useSessionBadges(
  sessions: SessionSummary[],
  messages: ChatMessage[],
  backendActiveSessionIds: Set<string>,
  pendingBySession: Map<string, number>,
): SessionBadgeMap {
  return useMemo(() => {
    const map: SessionBadgeMap = new Map();
    for (const s of sessions) {
      map.set(s.id, {
        running: false,
        approvals: pendingBySession.get(s.id) ?? 0,
        unread: s.unread_count ?? 0,
        error: s.last_error ?? null,
      });
    }
    // 即時來源：前端訊息流（running / error），覆蓋後端快照
    for (const m of messages) {
      if (!m.sessionId) continue;
      const b = map.get(m.sessionId);
      if (!b) continue;
      if (m.status === 'running' || m.status === 'waiting') b.running = true;
      if (m.status === 'error' && !b.error) b.error = m.content.slice(0, 240);
    }
    for (const id of backendActiveSessionIds) {
      const b = map.get(id);
      if (b) b.running = true;
    }
    return map;
  }, [sessions, messages, backendActiveSessionIds, pendingBySession]);
}
```

### 5.2 全域審批掃描（修 D-1 + D-3）

改寫 `App.tsx:1309` 的輪詢 effect：從「只輪詢活躍會話且集合空即停」改成**常駐單一輪詢**，一次拿兩份資料。

```tsx
// 全域狀態輪詢：活躍會話 + 待審批筆數。常駐（不再因集合為空而停止），
// 讓背景會話的待審批在使用者開啟該會話前就可見（原 D-1）。
const [backendActiveSessionIds, setBackendActiveSessionIds] = useState<Set<string>>(new Set());
const [pendingBySession, setPendingBySession] = useState<Map<string, number>>(new Map());

useEffect(() => {
  let cancelled = false;
  let timer: ReturnType<typeof setTimeout> | undefined;
  const poll = async () => {
    try {
      const [active, approvals] = await Promise.all([
        chatService.listActiveSessions(),
        chatService.listCommandApprovals(),
      ]);
      if (cancelled) return;
      setBackendActiveSessionIds(new Set(active));
      const counts = new Map<string, number>();
      for (const a of approvals.approvals) {
        if (a.status !== 'pending') continue;
        const sid = (a.context as Record<string, unknown> | undefined)?.session_id;
        if (typeof sid !== 'string' || !sid) continue;
        counts.set(sid, (counts.get(sid) ?? 0) + 1);
      }
      setPendingBySession(counts);
    } catch { /* 靜默：下次輪詢重試 */ }
    if (!cancelled) timer = setTimeout(poll, 5000);
  };
  void poll();
  const onFocus = () => { if (!cancelled) void poll(); };
  window.addEventListener('focus', onFocus);
  return () => {
    cancelled = true;
    window.removeEventListener('focus', onFocus);
    if (timer) clearTimeout(timer);
  };
}, [chatService]);
```

1. **側欄指示器**（經 `useSessionBadges`）
2. **`restorePendingForSession`**（`App.tsx:3322`）改為**直接吃 `pendingBySession`**，不再自己打 API——開啟會話時只需把該會話的 pending 審批轉成 `PendingRequest` 注入。原邏輯保留，僅把資料源換掉，並移除 `:3456-3463` 的 5s/15s 延遲重掃（全域輪詢已覆蓋）。

### 5.4 新增共用元件 `SessionStatusBadge`

新增 `frontend/src/components/SessionStatusBadge.tsx`：

```tsx
import { Loader2 } from 'lucide-react';
import type { SessionBadges } from '../types';
import { t } from '../lib/i18n';

interface Props {
  badges?: SessionBadges;
  className?: string;
}

/** 固定寬度的狀態槽：只渲染優先級最高的一種狀態（待審批 > 錯誤 > 進行中）。
 *  未讀不在此處競爭，由呼叫端獨立渲染於右側。 */
export function SessionStatusBadge({ badges, className }: Props) {
  if (!badges) return <span className={`session-status ${className ?? ''}`} aria-hidden="true" />;

  if (badges.approvals > 0) {
    return (
      <span
        className={`session-status session-status--approval ${className ?? ''}`}
        title={t('session_status.pending_approval', { count: badges.approvals })}
        aria-label={t('session_status.pending_approval', { count: badges.approvals })}
      >
        {badges.approvals > 9 ? '9+' : badges.approvals}
      </span>
    );
  }
  if (badges.error) {
    return (
      <span
        className={`session-status session-status--error ${className ?? ''}`}
        title={badges.error}
        aria-label={t('session_status.error')}
      >!</span>
    );
  }
  if (badges.running) {
    return (
      <span className={`session-status session-status--running ${className ?? ''}`} aria-label={t('session_status.running')}>
        <Loader2 size={13} className="session-status__spinner" />
      </span>
    );
  }
  return <span className={`session-status ${className ?? ''}`} aria-hidden="true" />;
}
```

### 6.1 版型

│ [槽16px]  會話標題（flex:1，截斷）      [未讀pill] [時間] │

## 8. 風險與對策

| 風險 | 影響 | 對策 |
|---|---|---|
| `main.py:277` 與 `agent/runtime.py:1226` 各自 new 一個 `CommandApprovalStore` 指向**同一個 JSON**，採 read-modify-write | 高併發下審批紀錄可能互相覆蓋 | 本次不修（既有問題）。若 Phase 1 觀察到遺失，再評估加檔案鎖或改單例 |
| 輪詢改為常駐後，每 5s 一次 `/command-approvals` 全量讀檔 | 審批紀錄上限 100 筆（`workspace.py:122`），檔小，可忽略 | 若未來紀錄變大，改為後端提供 `GET /approvals/pending/summary` 只回 `{session_id: count}` |
| `last_read_at` 與 `created_at` 皆為 ISO 字串比較 | 若未來 `created_at` 改為 local time 或非固定偏移，字典序失效 | 在 `unread_count()` 加斷言／註解鎖定「必須是 UTC ISO 8601」 |
| 側欄水平空間：`gap:10px` + 新增 16px 槽 + 未讀 pill | 窄側欄下標題可能被壓到很短 | Phase 1 實測側欄拖到最小寬度；必要時窄於 200px 時隱藏未讀 pill |
| `--destructive` / `--danger` 兩套紅色 | 誤用會導致換主題時顏色跑掉 | §6.3 列為硬性約束，code review 必查 |
